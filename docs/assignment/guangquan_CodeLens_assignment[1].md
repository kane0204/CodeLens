# 作业 1：产品使命、口号与策略设计（CodeLens）

**小组：光圈　作品：CodeLens**

## 1. 设计产品的使命和口号

### ● 使命
解决 AI 生成代码的黑盒问题，让开发者能看懂、能验证、能审查 AI 写出的项目代码。

### ● 口号
Make Code Visible.

---

## 2. 制定产品的策略

### ● 目标用户是？

主要用户是使用 AI 编码的开发者；直接相关用户包括代码评审者、技术负责人和项目接手者。

### ● 如何争取目标用户？
- 首批通过高校开发者社团、开源项目和 AI 编程社群触达使用 AI 编码的开发者；
- 以免费项目扫描和可分享的审查报告作为试用入口，跟踪“渠道触达—首次扫描—团队采用”的转化；
- 先以个人版建立口碑，后续通过团队版、私有部署和定制规则探索商业化。

### ● 公司/团队的优势是？
苏州大学计算机学院课程小组，具备 Python / TypeScript、静态分析、React、FastAPI 和自动化测试开发能力；小团队迭代快，能根据真实项目反馈快速校准规则。

### ● 竞争对手与差异化竞争

| 工具 | 核心定位 | 主要强项 | 与 CodeLens 的区别 |
|---|---|---|---|
| radon | 复杂度度量 | 圈复杂度、可维护性指数 | 只提供指标，不产出逻辑、结构和风险报告 |
| pyan | 调用关系分析 | 函数与模块调用图 | 主要提供单一调用关系视图 |
| pyreverse | UML 建模 | 类图、包图和继承关系 | 侧重结构表达，不做质量与风险审查 |
| Noodles | 控制流可视化 | 函数级控制流图 | 提供 CFG，不负责项目级证据链 |
| Sourcetrail | 代码导航 | 跨文件符号跳转和依赖浏览 | 侧重阅读导航，不直接给出质量判断 |
| **CodeLens** | **可审查的代码分析 Agent** | **逻辑、结构、质量与风险统一分析** | **一次解析、多视图、每条结论可回查源码** |


#### SWOT 分析：

| | 有利 | 不利 |
|---|---|---|
| 内部 | **优势**：静态核心确定可复现；结论带源码证据；逻辑、结构、质量和风险统一呈现 | **劣势**：当前以 Python 为主；动态调用与反射识别有限；部分规则阈值仍需校准 |
| 外部 | **机会**：AI 生成代码量持续增长，团队需要更快理解与审查生成代码 | **威胁**：IDE 插件、通用大模型和单一分析工具都在增强能力 |
