# 作业 2：定义产品（CodeLens）


对于 **使用 AI 编码的开发者与代码评审者**，
他们 **能生成代码，却难以确认 AI 写的逻辑、结构与风险**，
**CodeLens** 是一个 **本地运行的 Python 代码静态分析工具**，
它能够 **输出语句级逻辑、类图/时序图与质量风险报告，每条结论可回到源码行**，
不同于 **Noodles、Understand Anything 等偏「理解与展示」的工具**，
我们的产品 **核心分析确定可复现，并把逻辑、结构、AI 风险放在同一次解析里**。


## 产品定义七要素

### 1. 产品名称

**CodeLens**

### 2. 发布时间

MVP 计划 2026 年 11 月底发布

### 3. 目标客户 + 数量

| 客户 | 数量估计 |
|---|---|
| 使用 AI 编码的开发者（主要）、代码评审者与项目接手者 | 首批 3–5 个项目组（约 50 人），首年 500 名试用（待调研校准） |

### 4. 解决了什么问题 + 价值

问题：AI 代码能跑，但逻辑不透明、隐含假设多、风险难定位，评审只能逐行读。
价值：缩短评审与接手时间，减少带病合并。

### 5. 解决方案 + 类似产品、如何差异化

方案：一条命令完成「扫描 → 逻辑建模（语句/CFG/def-use）→ 结构图 → 复杂度/坏味/SOLID/AI 风险 → 报告」。
同类：Noodles、Understand Anything、Sourcetrail、pyreverse、pyan、radon。
差异：轻量级、核心分析确定可复现。

### 6. 何时交付 + 主要里程碑

| 阶段 | 时间 | 交付 |
|---|---|---|
| 分析 | W1–W2 | 5W1H、SRS、样例项目与标注 |
| 设计 | W3 | 架构、数据契约、CLI 骨架 |
| 开发 | W4–W5 | 逻辑抽取、类图/时序图、复杂度与规则 |
| 测试 | W6 | 集成测试、准确率与误报率验收 |
| 发布 | 2026-11 底 | v0.1（CLI + 报告） |
| 迭代 | 2026-12 起 | Web 预览、多语言、LSP/ISP 规则 |

### 7. 团队背景

苏州大学计算机学院课程小组
