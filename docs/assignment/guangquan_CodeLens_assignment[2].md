# 作业 2：定义产品（CodeLens）

**小组：光圈　作品：CodeLens**

对于 **使用 AI 编码的开发者与代码评审者**，
他们 **能生成代码，却难以确认 AI 写的逻辑、结构与风险**，
**CodeLens** 是一个 **面向 AI 生成代码的 Web 代码分析 Agent**，
它能够 **输出项目结构、语句级逻辑、设计检查与严重危害评估，每条结论可回到源码行**，
不同于 **Noodles、Understand Anything 等偏「理解与展示」的工具**，
我们的产品 **将确定性静态分析与按需 Agent 审查结合，把逻辑、结构、质量和风险放在同一份可追溯报告里**。


## 产品定义七要素

### 1. 产品名称

**CodeLens**

### 2. 发布时间

2026 年 11 月完成课程版并上线网页演示。

### 3. 目标客户 + 数量

| 客户 | 数量估计 |
|---|---|
| 使用 AI 编码的开发者（主要）、代码评审者与项目接手者 | 首批 3–5 个项目组（约 50 人），首年 500 名试用（待调研校准） |

### 4. 解决了什么问题 + 价值

问题：AI 代码能跑，但逻辑不透明、隐含假设多、风险难定位，评审只能逐行读。
价值：缩短评审与接手时间，减少带病合并。

### 5. 解决方案 + 类似产品、如何差异化

作品形式：Web 应用。用户导入项目文件夹后，系统完成源码扫描、AST/CFG/def-use 分析、结构关系构建、复杂度/坏味/SOLID/AI 风险检查，并通过 Agent 按需生成逻辑说明、设计检查和严重危害评估。
审查报告支持源码行回查、历史记录、断点续跑、缓存复用和 Markdown/JSON 导出。
同类：Noodles、Understand Anything、Sourcetrail、pyreverse、pyan、radon。
差异：核心静态分析确定可复现；模型只负责基于证据的表达，不修改静态事实；多类结果进入同一证据链。

### 6. 何时交付 + 主要里程碑

| 阶段 | 时间 | 交付 |
|---|---|---|
| 分析 | W1–W2 | 5W1H、SRS、样例项目与标注 |
| 设计 | W3 | 系统架构、接口、数据契约与页面原型 |
| 开发 | W4–W6 | 静态分析核心、React 工作台、Agent 审查与历史记录 |
| 测试 | W7 | Python/前端单元测试、集成测试和演示项目回归 |
| 发布 | 2026-11 | Web 应用、项目仓库、课程报告与演示环境 |
| 迭代 | 后续 | 多语言支持、规则阈值校准和团队协作能力 |

### 7. 团队背景

苏州大学计算机学院课程小组，具备 Python / TypeScript、静态分析、React、FastAPI 和自动化测试开发能力，采用小步迭代并依据真实项目反馈持续校准规则。
