## 1. 沟通管理计划

| 沟通内容 | 频度 | 方式 | 产出物 |
|---|---|---|---|
| 需求范围、5W1H 与验收标准 | 每周；变更即时 | 视频会议 + Issue | SRS 评审记录、需求变更单 |
| 架构、接口与数据契约 | 每周；重大改动即时 | 面对面评审 + PR | 架构文档、接口契约、ADR |
| 开发进度与阻塞 | 每天 | 站会 + IM + Kanban | 任务状态、阻塞清单 |
| 代码评审与合并 | 即时 | PR + Issue | 评审意见、合并记录 |
| 测试与缺陷 | 每天；高危缺陷即时 | Bug tracker + IM | 缺陷单、回归报告 |
| 发布准备与回滚 | 发布前专项 | 视频会议 + 邮件 | 发布清单、回滚方案、发布说明 |
| 用户反馈与复盘 | 每月 | Issue + 复盘会 | 反馈汇总、复盘报告、迭代计划 |

## 2. 风险管理计划

| 风险名称 | 维度 | 风险说明 | 影响 | 工作量 | 进度/成本 | 优先权 | 跟踪频率 |
|---|---|---|---|---|---|---|---|
| LLM API 不可用 | 外部因素 | 由于 LLM 服务商可能宕机、涨价或停服，可能发生说明层无法调用，从而导致总结缺失、交付延期。 | 高 | 低 | 中 | P1 | 每月 |
| Python 破坏性变更 | 技术 | 由于 Python 新版本可能改变 ast / symtable 行为，可能发生解析失真，从而导致图与指标错误。 | 高 | 中 | 中 | P2 | 每季度 |
| 供应链攻击 | 技术 | 由于开发依赖或 CI 工具链可能被投毒，可能发生凭据或源码泄露，从而导致安全事故。 | 高 | 低 | 中 | P2 | 每季度 |
| GitHub 服务中断 | 外部因素 | 由于 GitHub 可能服务中断或账号受限，可能发生仓库与 CI 暂不可用，从而导致协作与发布延期。 | 高 | 低 | 高 | P1 | 每月 |
| 代理或网络不可用 | 外部因素 | 由于代理或网络可能中断，可能发生无法推送与拉取，从而导致提交延期、版本分叉。 | 中 | 低 | 高 | P1 | 每月 |
| 核心成员长期缺席 | 资源 | 由于核心成员可能因病或实习长期缺席，可能发生关键模块无人维护，从而导致进度延期与知识断层。 | 高 | 高 | 高 | P1 | 每月 |
| 仓库或数据丢失 | 项目管理 | 由于磁盘故障或误操作，可能发生代码与文档丢失，从而导致返工与交付延期。 | 高 | 中 | 高 | P1 | 每月 |
| 合规或课程政策变化 | 外部因素 | 由于学校可能限制外部 API 处理代码，可能发生说明层需下线，从而导致功能调整与返工。 | 中 | 低 | 中 | P2 | 每学期 |
| 竞品免费替代 | 外部因素 | 由于大厂可能推出相近的免费工具，可能发生用户流失，从而导致项目价值下降。 | 高 | 中 | 中 | P2 | 每季度 |
