# 作业 4：产品实现与证据说明（CodeLens）

**小组：光圈　作品：CodeLens**

## 1. 作品形式

CodeLens 的最终作品形式是 **Web 应用**。用户在工作台导入项目文件夹后，可以查看项目总览、文件结构、调用与依赖关系、函数复杂度、质量问题和风险信息；配置模型后，还可以按文件或整个项目生成逻辑说明、设计检查和严重危害评估。

每条关键结论都带有文件和行号引用，可返回源码核对。系统支持历史记录、断点续跑、缓存复用以及 Markdown / JSON 报告导出。

## 2. 已实现内容

| 模块 | 实现内容 |
|---|---|
| 项目分析 | 扫描源码，识别文件、语言、函数、类、依赖和调用关系 |
| 逻辑分析 | 构建 AST、控制流、数据使用关系和函数摘要 |
| 结构与质量 | 展示类图、调用图、模块依赖、复杂度、坏味、SOLID 和健康度 |
| AI 审查 | 生成逻辑说明、设计检查与严重危害评估，并校验源码引用 |
| 连续使用 | 支持历史记录、缓存命中、检查点恢复和报告导出 |
| 使用安全 | 本机接口校验 Host、Origin 和访问令牌；只有用户确认后才将源码发送给外部模型 |

## 3. 技术实现

- 前端：React、Vite、Tailwind CSS，负责项目导入、报告展示、源码回查和审查进度。
- 后端：Python、FastAPI、Uvicorn，提供静态分析、Agent 审查、历史和同步接口。
- 分析核心：Python `ast`、`tokenize`、控制流、def-use、调用图和规则引擎。
- Agent：使用 LangGraph 编排上下文构造、模型生成、证据校验、补上下文和结果合并。
- 数据存储：保存项目历史、审查结果、缓存指纹和续跑检查点。

静态分析与模型表达分离。代码结构、复杂度、规则命中和引用范围由确定性程序生成；模型只根据这些证据组织文字，不修改静态事实。

## 4. Agent 工作方式

1. 静态分析先生成源码、IR、指标和规则事实；
2. 根据文件、目录、函数或项目范围构造上下文；
3. 检查缓存和历史检查点，复用已完成结果；
4. 调用模型生成逻辑、设计或风险内容；
5. 校验结构、证据和源码行号，不合格时补充一次上下文或重试；
6. 保存结果并通过流式事件向页面报告进度。

## 6. 质量保证

- 核心分析、接口和前端逻辑均有自动化测试；
- 规则结果区分事实与推断，并记录严重度、置信度、文件位置和覆盖缺口；
- AI 输出必须通过结构和引用校验，无法关联源码的结论会被丢弃；
- 模型或网络失败时保留静态分析结果，不生成伪造的替代结论；
- 对演示项目执行回归，验证导入、分析、逻辑解读、历史记录和导出流程。

## 7. 当前边界

CodeLens 不能执行代码，也不能证明程序在所有运行环境中的正确性。动态调用、反射、运行期配置和外部服务行为可能无法由静态分析还原。当前核心规则以 Python 为主，部分阈值仍需使用更多真实项目校准；AI 生成的文字会随模型变化，因此结论最终需要开发者结合源码复核。
