## US-01 获得项目源文件清单

**角色**：作为一名接手陌生项目的开发者  
**功能**：我希望提交本地项目文件夹后，查看实际纳入分析的 Python 文件清单  
**价值**：以便确认分析范围没有遗漏或混入无关文件

```gherkin
场景: 扫描并应用默认排除
  Given 样例项目包含多层目录的 .py 文件，以及 .venv、build、tests 下的 .py 文件
  When 我运行 codelens analyze ./demo
  Then 清单应包含所有未排除的 .py 文件，且每个文件只出现一次
  And .venv、build、tests 下的文件不应纳入
  And 结果应显示本次生效的排除配置

场景: 自定义排除
  Given 我传入两个匹配不同文件集合的 --exclude glob
  When 我运行扫描
  Then 两个集合的并集应被排除
  And 未匹配的文件应保留

场景: 空目录与无效路径
  Given 一个没有 Python 文件的目录，或一个不存在的路径
  When 我运行扫描
  Then 无文件时显示「未发现可分析的 Python 文件」
  And 路径无效时显示具体原因并以非零状态退出
  And 不应宣称分析成功
```

**INVEST**：可仅用文件树验证；输入、排除规则和性能边界明确；不捆绑解析。

## US-02 阅读带源码位置的函数逻辑说明

**角色**：作为一名使用 AI 编码的初学者  
**功能**：我希望阅读某个函数按源码顺序组织的逻辑步骤，并看到每步对应的位置  
**价值**：以便逐条核对代码实际做了什么

```gherkin
场景: 生成可复核的步骤
  Given 函数包含赋值、调用、条件和返回，且有跨行语句
  When 我生成逻辑说明
  Then 每一步应给出 AST 类型与行号范围
  And 每步的文件、函数全限定名与行号都能指向源码
  And 顺序与源码一致

场景: 分支归属
  Given if 与 else 分支中各有一次调用
  When 我阅读说明
  Then 两次调用分别归属于各自条件
  And 不描述为一次执行中必然依次发生

场景: 可复现与离线
  Given 不变的源码、配置和工具版本
  When 我连续生成两次
  Then 说明文件逐字节一致
  And 不发起网络请求、不执行被分析函数
```

**INVEST**：可输入固定逻辑模型验收；语句集合与样例数明确；排除完整数据流和副作用分析。

## US-03 查看类与继承关系

**角色**：作为一名项目接手者  
**功能**：我希望查看项目中的类和可静态确定的继承关系  
**价值**：以便快速建立对象结构的整体认识

```gherkin
场景: 展示类与继承
  Given 项目包含两个模块、三个类，父类与子类通过显式导入建立继承
  When 我导出类图
  Then 三个类及其成员应完整出现
  And 继承边端点与方向正确，构造样例继承边 100% 正确

场景: 同名与未知父类
  Given 不同模块存在同名类，且某父类由无法静态解析的表达式决定
  When 我查看类图
  Then 同名类应使用不同全限定标识，引用不串线
  And 未知父类不应猜测连接，并输出带位置的 warning

场景: 空结果与渲染
  Given 项目中没有类，或项目中有类
  When 我导出类图
  Then 无类时显示「未发现类」
  And 有类时 Mermaid 文件可渲染，重复导出顺序一致
```

**INVEST**：使用固定符号表可独立验收；只覆盖一种关系；不捆绑五类关系。

## US-04 查看函数圈复杂度与分级

**角色**：作为一名审查时间有限的代码评审者  
**功能**：我希望查看各函数的圈复杂度和等级  
**价值**：以便优先检查控制路径复杂的函数

```gherkin
场景: 计算与分级
  Given 一个无判定函数、一个仅含 if 的函数，以及 5/6、10/11、20/21、30/31、40/41 的边界样例
  When 系统计算圈复杂度
  Then 无判定函数为 1，单 if 函数为 2
  And 等级满足 A=1–5、B=6–10、C=11–20、D=21–30、E=31–40、F≥41

场景: 与 radon 对拍
  Given 覆盖条件、循环、异常、布尔表达式、推导式和 match 的固定样例集
  When 我与 radon 6.0.1 对比
  Then 每个函数的相对偏差不超过 5%
  And 保留逐函数比较记录

场景: 解析失败
  Given 某个函数无法解析
  When 系统生成指标
  Then 不应给出 CC=0 或 A 级来冒充低风险结果
```

**INVEST**：单函数样例即可计算与验收；参考版本和等级边界明确。

## US-05 导出可复核的审查报告

**角色**：作为一名需要提交评审材料的开发者  
**功能**：我希望将已有分析结果导出为 Markdown 报告和 JSON 数据  
**价值**：以便团队阅读结论、核对源码并复用结果

```gherkin
场景: 报告内容与排序
  Given 结果集中包含逻辑说明、指标和 critical/warning/info 风险记录
  When 我导出报告
  Then Markdown 应包含范围、配置、完成状态、逻辑摘要、指标与风险清单
  And 风险按 critical、warning、info 排列，同级按路径、行号、rule_id 排序
  And 未运行的检查标为「未执行」

场景: JSON 与可复现
  Given 相同输入、配置和工具版本
  When 我连续导出两次并通过 schema 校验
  Then 两次产物逐字节一致
  And JSON 与 Markdown 的 finding 数量、等级和位置一致
  And 每条 finding 应包含 rule_id、severity、evidence_type、file、line、actual、threshold、confidence、message、suggestion

场景: 写入失败
  Given 目标目录没有写权限，或写入过程中发生故障
  When 我导出报告
  Then 应明确报告失败与目标路径
  And 不应提示成功，不完整文件不作为有效报告
```
