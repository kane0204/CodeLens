# 软件设计文档（docs/software）

本目录存放架构、接口、数据与测试相关的设计文档。

## 规划中的文档

| 文件名 | 内容 | 负责人 | 计划周次 |
|---|---|---|---|
| `architecture.md` | 总体架构：CLI 入口、核心引擎、后端任务、前端预览、导出的模块划分与数据流 | 架构负责人 | W3 |
| `diagram-ir.md` | 图数据中间表示：节点/边/位置的字段定义、版本演进与兼容策略 | 引擎负责人 | W3 |
| `api-contract.md` | REST 接口：创建分析任务、查询进度、获取图数据、下载导出文件、错误码 | 后端负责人 | W3 |
| `data-model.md` | 数据模型：分析任务、项目元数据、图产物、导出记录；保留与清理策略 | 后端负责人 | W3 |
| `test-plan.md` | 测试方案：单元/集成/渲染/E2E 的划分与准确率回归门槛 | 测试负责人 | W3 |
| `deployment.md` | 运行环境、依赖（tree-sitter、Graphviz）、配置项与密钥管理 | 后端负责人 | W5 |

## 写作要求

1. 设计与需求对应关系须显式标注（引用 `docs/requirements/problem_definition.md` 的功能编号 F1–F7）；
2. 接口与 IR 属于跨模块契约，变更必须先改文档再改代码，并在 PR 中说明影响范围；
3. 架构图使用 Mermaid，便于版本对比；
4. 任何「推断出来的关系」都必须在数据模型中带来源与置信度字段。
