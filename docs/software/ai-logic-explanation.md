# AI 项目审查与逻辑解读

导入后先进行本机静态分析。工作台按需生成文件、文件夹或全项目 AI 解读。全项目审查共享一份源码阅读记录，分别生成逻辑说明、设计检查和风险评估。旧的解读接口 `POST /api/explain` 继续可用。

## 使用

1. 在初始化页选择项目文件夹并完成本机静态分析；首页不展示模型或 API 设置。进入结果页后，在顶部「模型设置」中填写兼容 OpenAI `chat/completions` 的 Base URL、模型名称及 API Key；地址支持 `/v1` 或完整 `/chat/completions` 端点。API Key 写入操作系统凭据库，后续启动无需重填。
2. 导入后先显示静态分析结果。启用自动审查时，AI 随后继续工作，可在「逻辑说明」查看进度、暂停和重试。
3. 项目级审查依次请求 `logic`（全项目逻辑解读）、`design`（AI 设计检查）、`risks`（严重危害风险评估）。每部分独立校验和保存，继续审查时复用已完成部分。
4. 未配置模型或审查失败时静态结果照常可用，不使用模板伪装成 AI 结论。
5. 「一键解读所有文件」从项目中的第一个文件开始，最多并行 3 项；全部文件解读完成后会自动执行一次项目级综合审查，一并生成设计检查和风险评估。设计、风险页面不再提供独立生成按钮，只显示自动生成状态。

配置全部留空时，后端尝试读取 `CODELENS_AI_ENDPOINT`（完整端点）、`CODELENS_AI_MODEL`、`CODELENS_AI_KEY`。自定义配置缺少地址或模型名称时直接提示错误，不混用服务端密钥；无认证的本地兼容服务可留空密钥。

## 请求与结果

`POST /api/review` 沿用本机 Host、Origin、令牌和请求体大小校验，响应为 `application/x-ndjson`，逐行发送 `progress` / `result` / `error`。

- 后端按输入预算分批读取已解析源码，按行切分并保留路径与行号。阅读记录过长时按模块分组进行分层摘要。生成每部分报告时按该部分相关性选择静态证据。界面分别显示静态证据省略、阅读记录压缩、阅读和摘要输出触顶、最终报告输出触顶。
- 三段分别要求：逻辑解读按「项目做什么 / 入口与主流程 / 模块如何协作 / 数据与异常 / 复核重点」组织；设计检查只讨论有源码或静态事实支持的结构与依赖问题；风险评估**只评估会造成严重危害的风险**，无严重危害时明确写「未检出」，不列中低危。
- 结果中的引用格式为 `[路径:L起始行-L结束行]`，后端 `citations_for` 校验引用落在本次实际发送的源码范围内；越界引用标为未验证，不提供可点击的源码跳转。文本经转义后渲染，不执行模型返回的 HTML。
- 前端移除了 AI 分析与审查的等待上限；后端对单次模型 HTTP 请求保留 1800 秒连接级兜底，用于避免端点不响应时线程永久挂起，不构成页面时间限制。

## 审查流程

项目、目录和文件的 AI 审查由 LangGraph 执行阅读和综合。单批源码直接作为报告材料，多批源码先形成共享的阅读记录。每部分输出通过格式校验后才计入进度。LangChain Core 格式化兼容 `chat/completions` 的消息，编排和校验在本机执行，LangSmith 在线追踪在此链路关闭。

适配较小上下文的模型时，在启动后端前将 `CODELENS_REVIEW_CONTEXT_TOKENS` 设为模型支持的窗口大小（默认 `32768`），将 `CODELENS_REVIEW_OUTPUT_RESERVE` 设为预留输出预算（默认 `4096`）。输入使用 UTF‑8 字节数保守估计各服务的 token 占用，并预留指令空间。具体生成上限由模型服务决定。

## 断点续跑

后端使用 Python 标准库 SQLite 保存已完成的阅读批次、分层摘要及各部分报告。使用项目历史时，检查点保存在项目历史数据库中。其他审查默认使用 `data/reviews.sqlite3`，可通过 `CODELENS_REVIEW_DB` 指定位置。数据库可能包含代码片段或路径，API Key 不写入数据库。

重启后，重新导入相同源码即可继续使用系统凭据库中的 API Key。点击文件或文件夹可恢复已经生成的解读，批量解读遇到已有结果时直接复用。未完成的任务从已保存的批次继续。源码、模型配置或分批规则变更后会使用新的检查点。

## 状态与数据边界

- 未配置、进行中、失败、取消均有明确提示；失败不以模板替代 AI 结果。
- 密钥写入 Windows Credential Manager、macOS Keychain 或 Linux Secret Service；不写入报告、项目文件或浏览器持久存储。系统凭据库不可用时，设置窗口会明确提示并要求重新运行启动脚本。
- 导入即意味着把项目源码分批发送到用户配置的模型服务；普通静态分析不调用模型，也不执行目标代码。
- 导出可分别选择逻辑说明、设计检查与风险评估；Markdown 和 JSON 只包含勾选章节，JSON 默认剔除源码；未覆盖维度显示「未覆盖」及原因，不生成推断条目。

## 验证

端到端验证使用本机假模型服务与真实应用 HTTP 接口，覆盖批量读取、进度事件、三段结果、引用范围校验、失败与取消、断点续跑，以及文本转义与旧请求隔离。不依赖真实服务商或密钥，也不声称真实模型的生成质量已被测试。

## OpenAI 兼容配置示例

在「模型设置」中填写接口提供商给出的基础地址和模型名，例如 `https://api.openai.com/v1` 与 `gpt-4o-mini`。也可以填写完整地址 `https://api.openai.com/v1/chat/completions`。使用本机模型时填写本机服务给出的地址、端口和模型名。API Key 请填入单独的密钥字段。

遇到限流或临时服务错误时，CodeLens 最多尝试三次。认证失败时，请核对密钥、模型访问权限和接口地址，再继续解读。
