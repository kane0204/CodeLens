# AI 项目审查与逻辑解读

当前界面不再按「选文件／选函数 → 生成解读」逐次调用，而是在导入项目时一次性完成全项目 AI 审查，产出三段结果供「逻辑说明 / 设计检查 / 风险评估」共享。旧的单文件解读能力仍以 `POST /api/explain` 兼容保留。

## 使用

1. 在初始化页选择项目文件夹，并在同页填写兼容 OpenAI `chat/completions` 的 Base URL、模型名称及 API Key；地址支持 `/v1` 或完整 `/chat/completions` 端点。
2. 导入后自动完成「静态分析 → AI 项目审查」，页面显示分阶段进度与预计剩余时间。
3. 结果分为 `logic`（全项目逻辑解读）、`design`（AI 设计检查）、`risks`（严重危害风险评估）三段，三页共享同一份阅读记录，互相印证而非各自重新生成。
4. 未配置模型或审查失败时静态结果照常可用，不使用模板伪装成 AI 结论。

配置全部留空时，后端尝试读取 `CODELENS_AI_ENDPOINT`（完整端点）、`CODELENS_AI_MODEL`、`CODELENS_AI_KEY`。自定义配置缺少地址或模型名称时直接提示错误，不混用服务端密钥；无认证的本地兼容服务可留空密钥。

## 请求与结果

`POST /api/review` 沿用本机 Host、Origin、令牌和请求体大小校验，响应为 `application/x-ndjson`，逐行发送 `progress` / `result` / `error`。

- 后端分批读取**导入的全部源码**：单文件最多 60000 字符（`MAX_SOURCE_CHARS`），每个阅读批次最多 40000 字符（`MAX_PROJECT_BATCH_CHARS`），按行切分并保留路径与行号；超出的部分不计入引用范围，不猜测未读到的代码。
- 三段分别要求：逻辑解读按「项目做什么 / 入口与主流程 / 模块如何协作 / 数据与异常 / 复核重点」组织；设计检查只讨论有源码或静态事实支持的结构与依赖问题；风险评估**只评估会造成严重危害的风险**，无严重危害时明确写「未检出」，不列中低危。
- 结果中的引用格式为 `[路径:L起始行-L结束行]`，后端 `citations_for` 校验引用落在本次实际发送的源码范围内；越界引用标为未验证，不提供可点击的源码跳转。文本经转义后渲染，不执行模型返回的 HTML。
- 前端移除了 AI 分析与审查的等待上限；后端对单次模型 HTTP 请求保留 1800 秒连接级兜底，用于避免端点不响应时线程永久挂起，不构成页面时间限制。

## 审查流程

项目、目录和文件的 AI 审查由 LangGraph 顺序执行阅读、综合、证据校验三个步骤。单批源码直接用于生成审查，多批源码先形成阅读记录。LangChain Core 负责将系统提示和用户材料格式化为兼容 chat/completions 的消息。编排和校验在本机执行，LangSmith 在线追踪在这条链路关闭。

## 断点续跑

后端使用 Python 标准库 SQLite，将已完成的阅读批次、截断标记和解读结果保存在项目目录的 `data/reviews.sqlite3`。数据库最多保留 256 项，可通过 `CODELENS_REVIEW_DB` 指定位置。数据库会包含 AI 生成的笔记与报告，可能带有代码片段或路径。API Key 不写入数据库。

重启后，重新导入相同源码并填写原来的模型配置和 API Key。点击文件或文件夹可恢复已经生成的解读，批量解读遇到已有结果时直接复用。未完成的任务从已保存的批次继续。源码、模型配置或分批规则变更后会使用新的检查点。

## 状态与数据边界

- 未配置、进行中、失败、取消均有明确提示；失败不以模板替代 AI 结果。
- 密钥仅存当前页面内存，刷新需重填；不写入报告、项目文件或浏览器持久存储。
- 导入即意味着把项目源码分批发送到用户配置的模型服务；普通静态分析不调用模型，也不执行目标代码。
- 导出可选是否包含 AI 结果，JSON 默认剔除源码；未覆盖维度显示「未覆盖」及原因，不生成推断条目。

## 验证

端到端验证使用本机假模型服务与真实应用 HTTP 接口，覆盖批量读取、进度事件、三段结果、引用范围校验、失败与取消、断点续跑，以及文本转义与旧请求隔离。不依赖真实服务商或密钥，也不声称真实模型的生成质量已被测试。
