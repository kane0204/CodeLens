# 分析评估与验收

## 可复现的评估集

`tests/fixtures/solid_labels.json` 描述五个来源：三个教学项目（设备契约、运输分派、混合职责）和两个本仓库真实源码（provider、HTTP server）。标注来自本次逐类源码审查，尚未经独立人工复核。每个类按五项规则记录期望线索，理由保存在标签文件。

运行 `python -B tests/evaluate_solid.py` 得到逐类命中、每条规则的 TP/FP/FN/TN、精确率、召回率及覆盖缺口。分母为零返回 null，不能当作 100%。固定基准结果保存在 solid-benchmark.json。

这是小规模回归基准，不能外推成真实项目准确率；指标只是对这些标签的一致性。尤其外部父类留下的 L/I 覆盖缺口，不因为没有命中就被解释为完成验证。后续应加入独立评审者、更多未参与规则开发的项目与误报样本，保留标签版本后比较。

## 指标与算法验证

`test_quality.py` 用手算样本验证 WMC、DIT、CBO、LCOM1，覆盖未知父类、共享/不共享字段、跨文件类关系、结构重复正反例及稳定性。`test_solid.py` 覆盖签名收窄、绑定、异步、跨文件继承、抽象接口和覆盖缺口。

重复检测仅是保留名字和字面量的 AST 结构匹配，不应以本基准声称能找全语义等价代码。静态类关系也是设计线索，不证明对象生命周期。

## 浏览器验收

真实 Chromium/Edge 测试不再依赖旧 CL.app 或假 DOM：目录上传与分页拖拽导入 → 本机真实分析 → 跨文件 AI 解读 → 已验证行号源码弹窗 → Markdown/JSON/CSV 下载 → SOLID/类指标/关系图 → 模型错误/取消 → 旧后台能力不兼容。

同时验证导出 AI 可选、源码默认移除、密钥不持久化、越界引用不成为可点击链接，以及迟到请求不覆盖取消状态。模型端使用本机假服务保证可重复，不声称真实服务商的可用性或生成质量已被测试。

CI 运行 Python 回归、两组专用前端测试与真实浏览器/布局检查。浏览器程序可由 CODELENS_BROWSER 指定；测试失败会令检查失败，不静默跳过。
