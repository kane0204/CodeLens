# CodeLens 非功能需求 · radon 借鉴部分

| 项目 | 内容 |
|---|---|
| 文档编号 | CL-SRS-NFR-R |
| 版本 | v1.0 |
| 范围 | 仅本人部分：从 radon v6.0.1 借鉴、可落为质量约束的 6 条；其余非功能需求由他人撰写，合并时并入总规范 |
| 上游 | `problem_definition.md` §2.9、`functional_requirements.md`（FR-R01～R06） |
| 日期 | 2026-10-17 |

> 编号用 `NFR-R0x`，避免与他人 `NFR-*` 撞号。

| 编号 | 借鉴的做法 | 质量要求 | 指标与目标值 | 测量方法 |
|---|---|---|---|---|
| NFR-R01 | 核心算法零 CLI 依赖，radon 的 Flake8 插件 73 行即可复用 | 引擎不依赖上层，内部不做 I/O 与格式化，可被第三方当库调用 | 跨层 import = 0；引擎层 `open`/`print` 调用 = 0；≤ 100 行示例可仅以库方式取到结论 | `import-linter` 检查 import 图；另写最小复用示例跑通 |
| NFR-R02 | 异常转为数据，单文件失败不影响整批 | 任一文件任一阶段失败，都不影响其他文件与进程 | 错误隔离率 100%：注入 5 类故障（语法、编码、超深嵌套、超大文件、权限）后正常文件结果完整 | 故障注入脚本 + 产物断言 |
| NFR-R03 | 输出按名排序、无时间戳，结果可复现 | 相同输入与配置，两次运行产物逐字节一致 | diff = 0（`run.json` 除外）；CI 对拍失败即阻断合并 | 连跑两次 `diff -r`；三平台矩阵 |
| NFR-R04 | 加一种指标约 30 行 | 新增指标的边际成本有上界 | ≤ 2 个文件、≤ 100 行，不改流水线与导出层 | W5 由非作者实现一条并记录改动面 |
| NFR-R05 | visitor 测试按 AST 节点类型逐条断言 | 判定点覆盖到每一种语法结构，而非只覆盖行数 | 判定点节点类型覆盖 100%（`if`/`elif`/`else`/`for`/`while`/`try`/`except`/`boolop`/推导式/`match`）；引擎行覆盖 ≥ 80% | 节点类型清单与表驱动用例交叉核对；`pytest --cov --cov-branch` |
| NFR-R06 | 逐文件 yield 结果，不在内存留全量 AST | 规模增长时时间与内存近线性，单文件不拖垮整体 | 200 文件 ≤ 120 s；单文件 p95 ≤ 2 s，超 30 s 跳过并记 `timeout`；峰值内存 ≤ 1.5 GB，200→400 文件不翻倍 | `run.json` 分阶段耗时；`psutil` 采样两个规模对比 |
