# 单元测试（tests/unit）

## 已提供的回归检查

`test_engine.py` 覆盖真实 AST 指标、逻辑行号、错误隔离、不执行源码、编码、依赖/调用/继承、循环依赖、变量遮蔽、规则和输入边界。

仓库根目录运行：`python -B -m unittest discover -s tests -p 'test_*.py' -v`。下文保留完整测试规划。

针对解析、逻辑建模、指标、规则与导出的测试，快速、无外部依赖。

## 覆盖优先级

1. **解析与符号解析**：import、别名、嵌套作用域、装饰器、同名符号；
2. **逻辑模型**：语句轨迹顺序、if/elif/else 分支、循环、try/except、return/break/continue；
3. **数据流**：参数 → 局部变量 → 返回值；字段读写；跨函数调用参数传递；
4. **副作用识别**：函数调用、属性赋值、`with open`、网络/数据库调用；
5. **隐含假设**：直接解引用、下标访问、未校验参数；
6. **关系图**：继承/实现/组合/关联/依赖判定；
7. **指标**：CC、认知复杂度、嵌套、长度、WMC/DIT/CBO/LCOM 的边界情况；
8. **坏味与 SOLID**：每类规则至少 3 个正例与 3 个反例；
9. **AI 风险规则**：A1–A8 各 3 个正例与 3 个反例；
10. **证据等级**：事实/推断的标注与报告字段完整性；
11. **导出**：Mermaid/PlantUML 语法合法与特殊字符转义。
12. **确定性**：同一输入连续运行两次，`logic.json` 与 `logic.md` 逐字节相同。

## 约定

- 框架：pytest；
- 命名：`test_<模块名>.py`，测试函数 `test_<行为>_<期望>()`；
- 逻辑模型测试使用最小代码片段，断言步骤的**顺序与行号范围**，不能只断言数量；
- 指标测试写出手算结果作为断言；
- 规则测试片段放在 `tests/fixtures/`，正反例数量记录在 `docs/algorithm/evaluation.md`。
